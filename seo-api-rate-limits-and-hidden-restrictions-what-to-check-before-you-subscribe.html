SEO API Rate Limits and Hidden Restrictions: What to Check Before You Subscribe

Pricing pages tell you what an SEO data API costs. They rarely tell you how fast you can use it, how long you can keep the data, or what happens when you hit a cap. Those details often matter more than the monthly fee, especially for agencies running jobs across dozens of projects.

This guide collects the restrictions that tend to surprise teams after they have already subscribed.

Request Rate Limits

Every provider caps how quickly you can send requests, and the numbers differ widely. DataForSEO allows up to 2,000 requests per minute on most APIs, with a cap of 30 simultaneous requests on heavier endpoints like Backlinks and DataForSEO Labs. SE Ranking allows 10 requests per second on its Data API and 5 per second on its Project API. Semrush caps the Standard API at 10 requests per second and 10 concurrent requests, which can slow down bulk data retrieval.

A rate limit does not make an API bad, but it does shape how you design your scripts. Plan for batching, caching, and retries with backoff, and test your slowest job before you commit.

Quotas, Units, and What Happens When They Run Out

Most providers meter usage in units, credits, or rows, and each handles an empty balance differently. SE Ranking returns an HTTP 400 “Insufficient funds” error and pauses access until the next cycle. Semrush returns ERROR 132 for API v3 or a 403 error for API v4. Moz lets you check your remaining quota in real time with the quota.lookup method, which makes monitoring easier.

Expiry rules matter just as much. Semrush units expire at the end of each month, and Ahrefs add-on units expire after three billing months. DataForSEO’s $50 minimum top-up, by contrast, never expires. A balance that disappears can quietly raise your real cost.

Data Storage and Caching Rules

Some restrictions concern what you do with the data after you receive it. Semrush limits data caching to one month unless you obtain written consent, which is a problem for any product that stores history. DataForSEO keeps results as JSON for 30 days and raw HTML for 7 days. Mangools uses a 24-hour cache, so identical requests within a day are not charged twice.

Before you build a reporting product on top of an API, check these points:

  • How long you may store the data you collect
  • Whether you may display it to clients or resell it
  • How long the provider keeps results available for re-download
  • Whether caching is encouraged, tolerated, or restricted

Access Requirements and Hidden Prerequisites

Some APIs are not available simply because you want them. Ahrefs requires an Enterprise plan. Semrush requires a Business subscription before you can buy API units. SpyFu includes API access only on its Professional plan, and the lower-tier Basic plan does not include it. Mangools does not publish API pricing at all, so you must fill out a contact form first.

The Backlinks API at DataForSEO also requires a $100 monthly top-up. These prerequisites can double the true entry cost, so always ask what must be purchased before the first request is possible.

How to Run a Fair Test

The best way to find hidden limits is to run a pilot. Pick two providers and send them the same batch of queries. Note how long each job takes, how many credits or units it uses, and whether any errors appear. Then repeat the test at a higher volume to see where throttling begins. A short pilot costs little and often reveals more than hours of reading documentation.

The Bottom Line

A cheap API with restrictive limits can cost more than an expensive one that fits your workflow. Check rate limits, expiry rules, storage terms, and access prerequisites before you subscribe, and test with real jobs. The few minutes you spend reading the fine print can save weeks of rework later.
